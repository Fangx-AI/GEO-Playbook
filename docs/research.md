# 📄 论文与开源代码：GEO 的学术源头

> [GEO 学习地图](../README.md) › 测量与研究 › 论文

**“GEO”这个词来自哪篇论文？后续研究推翻或修正了什么？按问题选读 8 项论文与作者代码。**

| ⏱ 用时 | 👤 适合谁 | 📦 做完你手里有 |
| --- | --- | --- |
| 每篇 30–60 分钟 | 研究者、技术负责人、想看懂原理的运营 | 一份阅读顺序 · 论文证据卡模板 · 三个可做的复现实验 |

**先记住这 3 条**

1. **GEO 原论文**（KDD 2024）定义了问题、改写方法和“可见度”指标；它的提升发生在实验设置里，不等于商业平台流量。
2. **SAGEO Arena**（KDD 2026）在“检索 → 重排 → 生成”全流程里评估，同一种改写在不同阶段可能效果相反。
3. **ALCE**：有链接、来源支持这句话、关键事实都有来源，是三件不同的事。

---

## 学习目标

读完后，你应能解释一项 GEO 技巧改动了哪一阶段、论文实际测量了什么，以及结论能推广到哪里；也能把论文中的想法转化为一个可以失败、可以复查的实验。

先区分四个问题：页面是否能被发现；进入候选集合后是否被检索和选中；进入上下文后是否被准确使用和引用；用户看到回答后是否访问或采取行动。只验证其中一个环节的论文，不能自动回答其余问题。

## 先修知识与阅读顺序

- 能区分抓取、索引、检索、重排、生成、引用；不必先掌握模型训练。
- 能读百分比、百分点、分母、基线与对照组；不熟悉时先看[测量课](measurement.md)。
- 运营读者先读必读资源的摘要、实验设置、局限；研究读者再读公式、附录、代码与数据划分。
- 建议顺序：GEO 原论文 → SAGEO Arena → ALCE → 按问题选择 RAG、长上下文、电商和复现代码。

## 必读三项

### 1. GEO: Generative Engine Optimization

[论文全文，2024 年修订版](https://arxiv.org/html/2311.09735v3)

`📊 研究` `进阶` `英文` · KDD 2024 原始研究论文

**📌 要点：** 阅读第 2—3 节的来源改写、候选来源、重复采样及可见度指标；理解引用相关字数和位置如何计分。

**⚠️ 不能推出：** 特定实验的可见度提升不等于商业平台的流量、推荐或收入提升；当时的在线验证不能代替今天的复测。新增数据和引语仍须真实、相关、可溯源。

### 2. SAGEO Arena: A Realistic Environment for Evaluating Search-Augmented Generative Engine Optimization

[论文全文，2026 年 8 月修订版](https://arxiv.org/html/2602.12187v2)

`📊 研究` `研究` `英文` · KDD 2026 原始基准论文

**📌 要点：** 阅读第 3、5 节，研究保留网页结构的检索—重排—生成流程，检查同一种改写在不同阶段是否产生相反效果。这是已核实的后续 GEO 基准。

**⚠️ 不能推出：** 其端到端指自建流程，没有完整复现商用搜索私有排序与用户行为信号；不能推出某种 schema 必然增加真实平台曝光。

### 3. Enabling Large Language Models to Generate Text with Citations（ALCE）

[原始论文](https://arxiv.org/abs/2305.14627)

`📊 研究` `进阶` `英文` · EMNLP 2023 原始评估论文

**📌 要点：** 分开评价流畅性、正确性和引用质量，理解“有链接”“来源支持这句话”“关键事实都有来源”三者的差异。

**⚠️ 不能推出：** 自动蕴含判断需要复核；来源支持回答不代表来源自身可靠。回答质量指标不能直接当作品牌商业可见度评分。

## 扩展资源：按问题选读

### 4. GEO 作者代码与 GEO-bench 数据入口

[GEO-optim/GEO](https://github.com/GEO-optim/GEO)

`📄 资料` `研究` `英文` · 作者开源实现与数据入口

**📌 要点：** 对照 `src/run_geo.py`、`src/geo_functions.py` 和 `geval_prompts/` 检查改写与评分；README 提供 GEO-bench 数据入口。

**⚠️ 不能推出：** 旧服务和依赖未必可用。固定提交、记录替换项，并标注改编实验；不要在测试集反复选提示后又把它当作未见测试。

### 5. SAGEO Arena 作者实现

[happysnail06/SAGEO_Arena](https://github.com/happysnail06/SAGEO_Arena)

`📊 研究` `研究` `英文` · 论文关联的作者实现

**📌 要点：** 查看语料、优化、检索与生成配置，区分“只替换上下文”和“把改写文档重新送入检索”两种实验。

**⚠️ 不能推出：** 先确认数据许可、硬件和调用成本，再跑小子集；只重跑生成、未更新检索结果，不能称为端到端验证。

### 6. E-GEO: A Testbed for Generative Engine Optimization in E-Commerce

[论文全文，2026 年 7 月修订版](https://arxiv.org/html/2511.20867v2)

`📊 研究` `研究` `英文` · 原始数据集与实验预印本

**📌 要点：** 阅读商品查询与候选评价协议，让测试题覆盖预算、用途、偏好和排除条件，理解有约束的推荐。

**⚠️ 不能推出：** 候选商品的排序提升不等于真实平台抓取、推荐或成交；跨域结论仍依赖数据与引擎设置，不能靠虚构商品卖点提高分数。

### 7. Retrieval-Augmented Generation for Knowledge-Intensive NLP Tasks

[RAG 原始论文](https://arxiv.org/abs/2005.11401)

`📊 研究` `进阶` `英文` · NeurIPS 2020 原始机制论文

**📌 要点：** 理解参数记忆与外部知识如何参与生成，区分“模型知道某事实”和“本次使用了某网页”。

**⚠️ 不能推出：** 这是具体检索增强模型的研究，不是所有商用产品的架构说明。不能从品牌出现反推它来自训练、实时检索或指定数据库。

### 8. Lost in the Middle: How Language Models Use Long Contexts

[原始论文](https://arxiv.org/abs/2307.03172)

`📊 研究` `进阶` `英文` · TACL 原始受控实验论文

**📌 要点：** 理解上下文位置与长度如何影响信息使用，借鉴“保持事实不变、只改变证据位置”的实验思路。

**⚠️ 不能推出：** 输入上下文位置不等于网页屏幕位置，旧模型结果须在新模型复测；不能据此推导“品牌写在网页第一句即可获推荐”。

## 读论文时必须填写的证据卡

下面是本项目建议的阅读模板，不是任何论文的官方打分标准。

| 字段 | 必须回答的问题 |
| --- | --- |
| 研究对象 | 改网页正文、标题、结构、检索器、提示词，还是模型？ |
| 系统范围 | 离线固定候选／本地端到端系统／在线 API／面向用户产品？ |
| 输入分布 | 哪些语言、行业、题型、时间段和地域？品牌题与非品牌题是否分开？ |
| 基线和对照 | 与原文、随机改写还是强基线比较？还有哪些东西一起变了？ |
| 指标 | 名称、公式、分母、去重方法；是否包含真实用户？ |
| 统计单位 | 查询、查询家族、文档、用户还是调用？重复是否独立？ |
| 改善与代价 | 引用变多时，事实准确性、检索命中、成本或用户体验是否变差？ |
| 可复现性 | 数据与代码是否可取得？版本、提示、参数、失败样本是否公开？ |
| 有效范围 | 能支持什么结论？没有测哪些平台、语言、阶段或商业结果？ |

阅读顺序可从“结论→实验设置→指标→局限→方法”开始。遇到提升数字，先问分母与基线，再决定是否值得复现。预印本、作者代码和同行评审论文分别记录；发表状态不能替代对实验适用范围的判断。

## 三个可做的练习

1. **拆解一个流行结论。** 从 GEO 原论文挑一个结果，写出实验条件与指标。将它改写为限定范围的中文结论，并举出一个该结果无法回答的问题。
2. **做最小机制实验。** 选 8—12 个问题和一组可公开使用的固定来源，只修改一个变量，例如把已有、可证实的结论改写得更清晰。对原文和改写运行配对重复测试，保留原文、改写、完整回答、引用与失败。注明这是离线机制实验。
3. **寻找反例。** 至少保存一个引用增加但事实准确性下降、或生成阶段得分增加但检索表现变差的真实实验样本；若没有发现，写“本样本未观察到”，不要制造反例。

## 验收标准

- 能用自己的话区分“被检索”“被提及”“被引用”“被推荐”“带来转化”。
- 完成三张证据卡，至少包含原始 GEO 和一个后续基准。
- 能指出固定候选实验和商用平台观察之间至少两个缺失环节。
- 每项复现实验都有原始材料、版本记录、失败记录和可重算的指标。
- 结论能被数据否定，且没有把某一实验中的收益写成普遍承诺。
