# 🧰 GEO 提示词库：10 个复制就能用的工作提示词

> [GEO 学习地图](../README.md) › 工具箱 › 提示词库

**每个提示词都解决 GEO 工作流里的一个具体环节。把 `{{ }}` 里的内容换成你的资料，整段粘贴给任意大模型即可。**

所有提示词遵循同一条底线：**只用你给的资料，不发明功能、客户、数据和承诺；资料不够就列出缺口。** 这条底线就是 GEO 的核心，因为 AI 搜索引用的是事实，夸大的文案只会被忽略或被说错。

| # | 提示词 | 什么时候用 | 产出 |
| --- | --- | --- | --- |
| P1 | [从客服记录挖出真实问题](#p1) | 不知道用户会问 AI 什么 | 分好组的问题表 |
| P2 | [整理事实卡](#p2) | 资料散在合同、后台、聊天记录里 | 一张带来源的事实卡 |
| P3 | [把广告文案改成决策页](#p3) | 页面全是“领先、强大、可靠” | 改后正文 + 逐句核查表 |
| P4 | [给编辑列改稿任务单](#p4) | 有一批旧文章要刷新 | 最多三条可执行任务 |
| P5 | [审稿：揪出夸大和无来源的句子](#p5) | 发布前最后一关 | 问题句清单 + 改法 |
| P6 | [只基于事实卡写 FAQ](#p6) | 需要 FAQ、帮助文档 | 问答对 + 来源编号 |
| P7 | [核查 AI 回答里的引用](#p7) | AI 提到你了，但说得对吗 | 逐条“支持/部分/不支持” |
| P8 | [写不踩雷的对比页](#p8) | 用户总问“和 X 比怎么样” | 有出处的对比表 |
| P9 | [设计测量题集](#p9) | 要开始测 GEO 效果 | 四类固定题 |
| P10 | [诊断 AI 为什么说错了](#p10) | AI 把价格、功能、营业时间说错 | 错误来源与修复动作 |

> 💡 用法建议：P3、P5、P6、P8 建议**关闭联网**或明确要求“仅使用给定资料”。P7、P10 需要你先把 AI 的原回答和来源正文复制进来。

## P1 · 从客服记录挖出真实问题

```text
你是用户研究员。下面是我们 {{产品/门店/服务名}} 的客服记录、销售聊天或访谈摘录（已脱敏）。

任务：
1. 提取用户真实提出的问题，保留原话，不改写成书面语。
2. 每条标注：来源编号、提问者角色（如采购负责人/普通用户）、TA 正在做的决定
   （是否需要 / 是否适用 / 预算 / 对比 / 怎么开始 / 出了问题 / 能否退出）。
3. 按“正在做的决定”分组，不按关键词分组；同义问题合并，记下出现次数。
4. 标出哪些问题里没有出现我们的品牌名（这类“非品牌问题”最重要）。

约束：
- 只从材料中提取，不要补充“用户可能会问”的问题。如果你想补充，单独放在
  “候选题（非真实记录）”一节，并说明理由。
- 同一个人连续追问算一次，不要重复计数。

材料：
{{粘贴客服记录}}
```

## P2 · 整理事实卡

```text
你是产品资料编辑。请从下面的原始资料中整理一张“事实卡”，作为官网、FAQ、商店、
地图、公众号等所有对外渠道的唯一数据源。

输出表格，列为：编号(F01…) | 事实 | 适用条件/限制 | 来源（文件名+位置） | 状态
状态只能是：已确认 / 资料冲突 / 未知。

必须覆盖的字段（缺失就标“未知”，不要猜）：
- 是什么、给谁用、不适合谁
- 价格：计费单位、包含什么、额外收费、币种、生效日期
- 使用条件：系统/地区/营业时间/服务范围/需要准备什么
- 明确不支持或不包含的事项
- 数据、隐私、退出或取消规则
- 可公开的证据：截图、实拍、测试记录、案例

约束：
- 两份资料说法不一致时，两条都列出并标“资料冲突”，不要自行选择。
- 销售口头说法、宣传语不能直接标为“已确认”。

原始资料：
{{粘贴产品说明、价目表、合同条款、后台截图文字等}}
```

## P3 · 把广告文案改成决策页

> 完整教学版（含参考答案和审核表）见 [改稿实战课](../docs/content-rewrite.md)。

```text
你是帮助文档编辑。请仅依据下方事实卡，改写一段页面正文。
不要联网，不要补充事实卡中没有的功能、成绩、客户或承诺。

读者：{{具体读者，如：20 人客服团队的负责人}}
页面任务：{{读者读完要能做出的决定，如：判断是否值得试用、算清月费、知道迁移限制}}
必须回答：{{3–6 个具体问题}}

事实卡：
{{粘贴 P2 的输出}}

原稿：
{{粘贴原文}}

请按顺序输出：
1. 不超过 {{600}} 字的正文，带具体标题，最多四个小标题。
2. 核查表：改后句子 | 事实编号 | 必要条件。一句有两个主张就拆开。
3. 待确认清单：事实卡中“未知/资料冲突”的项必须留在这里，不得写进正文。

写作要求：
- 第一段直接说明适合谁、不适合谁。
- 禁用“领先、最佳、所有、全面、无损、极大提升”等无法核实的词。
- 价格给出算式；限制条件紧贴对应能力写，不放到页尾。
- 可以给出试用建议，但标明是建议，不能声称已替用户测过。
```

## P4 · 给编辑列改稿任务单

```text
你是内容编辑。目标读者是 {{读者}}。
本页唯一目标：{{读者读完能完成的一件事}}。

我会提供页面正文、相邻页面摘要和已核实的资料。
请输出最多三条改稿任务，每条包括：
1. 需要修改的原段落；
2. 读者具体卡在哪里；
3. 可直接插入的新段落或例子；
4. 所依据的已提供资料；
5. 编辑怎样验收（可操作、可检查）。

约束：不要推测流量、引用率或产品能力；资料不足时标出具体缺失的事实；
不改 URL，不把相邻页面承担的任务搬进来；删掉“肯定提升 AI 排名”等无证据承诺。

页面正文：{{}}
相邻页面摘要：{{}}
已核实资料：{{}}
```

## P5 · 审稿：揪出夸大和无来源的句子

```text
你是严格的事实审核编辑。请逐句检查下面的待发布稿件，对照事实卡找出问题。

输出表格：原句 | 问题类型 | 说明 | 建议改法
问题类型只能是：
- 无来源：事实卡里找不到依据
- 夸大：最高级、绝对化或无法验证的形容（最好、全面、100%、所有）
- 漏条件：能力被写出，但紧邻的限制条件被省略
- 冲突：与事实卡矛盾
- 承诺越界：涉及安全、效果、收益、医疗健康等无法保证的承诺
- 计算错误：价格或数字算错（请写出正确算式）

最后给出：可以直接发布 / 修改后发布 / 退回补资料，三选一，并说明理由。

事实卡：{{}}
待审稿件：{{}}
```

## P6 · 只基于事实卡写 FAQ

```text
请根据下面的真实用户问题和事实卡，为 {{页面名}} 写 FAQ。

要求：
- 问题使用用户原话或接近原话的口语问法，不要改成“关于本产品的价格政策”这类标题。
- 每个回答第一句直接给结论（能/不能/多少钱/怎么做），再补条件和下一步。
- 每个回答末尾用 [F编号] 标注依据；没有依据的问题不要回答，放进“待补资料”列表。
- “不能”“不支持”也要如实回答。帮用户正确排除，本身就是有价值的答案。
- 每个回答不超过 120 字。

用户问题：{{粘贴 P1 的输出}}
事实卡：{{粘贴 P2 的输出}}
```

## P7 · 核查 AI 回答里的引用

```text
你是引用核查员。下面是某个 AI 产品对一个问题的完整回答，以及它引用的每个来源的正文摘录。

请：
1. 把回答拆成独立的事实断言（一句含两个事实就拆成两条）。
2. 对每条断言，找出它旁边标注的引用，判断：
   支持 / 部分支持 / 不支持 / 无引用 / 来源无法访问
3. 对“部分支持”和“不支持”，引用来源原文说明差异在哪。
4. 标出引用的是原始来源还是转载，以及来源发布日期是否已过期。

输出表格：断言 | 引用编号 | 判定 | 来源原文依据 | 备注
最后统计：断言总数、被支持数、无引用数。

注意：只依据我给的来源正文判断，不要用你自己的知识替来源“补全”。
你的判断仍需人工抽查，不能直接当作最终结论。

问题：{{}}
AI 回答全文：{{}}
来源 1（URL + 正文摘录）：{{}}
来源 2：{{}}
```

## P8 · 写不踩雷的对比页

```text
请根据下面的一手资料，写一张 {{我们的产品}} 与 {{对比对象}} 的对比表，
帮助读者按自己的条件做选择，而不是证明我们最好。

要求：
- 对比维度从用户真实问题出发：{{如：价格单位、部署方式、导出、协作、系统要求}}
- 每个单元格注明来源编号和核对日期；资料里没有的填“未确认”，不要推测。
- 必须如实写出我们不支持、对方支持的项。
- 最后一节写“怎么选”：什么条件下选我们，什么条件下选对方。
- 禁止使用“完胜、碾压、最佳”等措辞；不编造测评数据和用户评价。

我们的资料：{{}}
对方的官方资料（含 URL 和核对日期）：{{}}
```

## P9 · 设计测量题集

```text
我要固定一组问题，定期在 {{目标 AI 平台}} 上观察 {{品牌/门店/产品}} 是否被提及、引用、说对。

请基于下面的真实用户问题，设计 {{12–24}} 道测量题，分四类：
A. 非品牌发现题：不出现我们的名字，描述用户的真实需求和约束（预算、地区、用途）
B. 品牌事实题：问我们的价格、条件、限制等可以对照事实卡判对错的问题
C. 限制/排除题：我们其实不适合的场景，正确答案应该是“不推荐我们”
D. 故障/使用题：用户用了之后会遇到的问题

每道题输出：编号 | 类别 | 完整问句 | 判定标准（怎样算答对/算推荐） | 对应事实编号

约束：
- 不要写“请推荐 XX”这类带答案的问句。
- 问句用用户口语，保留地区、预算等约束。
- C 类至少占 20%：一套只会让我们“赢”的题集没有测量价值。

真实用户问题：{{粘贴 P1 的输出}}
事实卡：{{粘贴 P2 的输出}}
```

## P10 · 诊断 AI 为什么说错了

```text
某 AI 产品在回答“{{问题}}”时，把我们的信息说错了。请帮我定位错误可能的来源，并给出修复动作。

AI 的原回答：{{}}
它展示的引用来源（URL + 正文摘录 + 页面日期）：{{}}
我们当前的正确事实（事实卡）：{{}}
我们自己所有渠道上的相关表述（官网、帮助、商店、地图、公众号等，附日期）：{{}}

请输出：
1. 错误清单：AI 的说法 | 正确事实 | 错误类型（过期 / 渠道之间矛盾 / 同名混淆 / 第三方错误 / 无来源编造）
2. 每条错误最可能来自哪个来源，以及判断依据；无法判断就写“无法判断”，不要猜平台内部机制。
3. 修复动作：先改我们能控制的源头资料，写清改哪个渠道、哪一句、改成什么。
4. 复测计划：修复后用哪些问题、在什么条件下复查。
```
